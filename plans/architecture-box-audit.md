# 星羲弦沚架构逐框验收矩阵

状态含义：`已实现` 表示存在可调用代码、持久化或用户入口，并有自动化测试；`宿主能力` 表示由运行环境提供；`延期` 仅适用于本轮明确排除的 GLB 三维渲染。

## 1. 基础设施层

| 方框 | 状态 | 实际落点 |
|---|---|---|
| 计算资源 | 宿主能力 | Gateway/Frontend 可本地或 Compose 部署；并发、worker 和资源由部署配置控制 |
| 对象存储 | 已实现 | `deerflow.object_storage`、对象元数据表、上传/OCR 页图像均走对象存储抽象 |
| 关系数据库 | 已实现 | SQLite 默认；SQLAlchemy/Alembic 管理业务表和版本 |
| 向量数据库 | 已实现 | 向量索引状态、版本、embedding 行与 SQLite 向量适配器；混合检索实际调用 |
| 图数据库 | 已实现 | 实体/关系/证据邻接表持久化，NetworkX 执行 1-3 跳有界遍历；不是独立图数据库服务 |
| 日志检索/CDN | 已实现/宿主能力 | RunJournal 持久化请求、模型、工具事件并支持运行事件 API；静态资源 CDN 属部署层配置 |

| 碑刻拓片/实景资料 | 已实现 | 图片、PDF、数字文档上传；版权、机构、可见范围与授权用途可登记 |
| OCR 校对 | 已实现 | 扫描页渲染、视觉 OCR、失败页重试、清洗、切分、逐页/逐块人工复核 |
| 出处绑定 | 已实现 | evidence 绑定 document/chunk/卷目/章节/页码，发布门禁禁止未审核内容进入版本 |

| 方框 | 状态 | 实际落点 |

## 非三维验收边界

本轮唯一延期项是 GLB 的真实三维渲染。其余方框均要求至少存在一个可调用后端路径；用户可见能力还必须有前端入口。没有真实文献时，只允许写入 `pending` / `inferred` 演示数据，不得标记为已审核历史事实。
