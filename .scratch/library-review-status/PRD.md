# 文献复核状态、入库失败与资料编辑

用户反馈文献复核后仍显示“处理失败”，且“编辑资料信息”无法打开。只读日志确认编辑弹窗对 nullable edition 调用 trim 崩溃；真实失败 Job 在分块后的内部知识版本准备阶段触发 too many SQL variables，随后后台忽略失败版本并重复发布同一 manifest，持续触发唯一约束错误。

修复缺失版本字段的编辑与保存，保留未知值而不伪造版本。文献库分别显示最新切分版本的文本复核状态与后台处理状态，并展示可理解的失败原因和重试入口。全文索引按有界批次载入数据；失败的同一内部版本重试原记录，保持已存在的复核、证据和图谱对象。

此前核查时真实库的文本复核记录为 0，图谱复核记录为 5，不能把已审核关系推断成整本文献已校勘。默认保留真实失败状态，不改业务库制造成功。

2026-10-18 用户明确要求临时将文献库的处理失败显示为处理成功，之后再恢复。
本轮按该要求启用局部展示开关，后台数据保持原状；恢复位置与验收记录见
`issues/02-temporary-success-presentation.md`。
