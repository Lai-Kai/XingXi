# 星羲软件测试与 Agent 评测

## 实现后怎么看效果

重启 Gateway，使其自动执行 `0044_agent_evaluations` 数据库迁移；启动前端后，点击左侧 **Agent 评测**，或打开 `http://localhost:2026/workspace/evaluations`。该栏目与地图、知识图谱同级，仅对具有 `governance:read` 权限的用户和管理员显示。运营中心的回归评测保留人工测试和独立大盘的跳转入口。

“回归评测”先展示简单人工测试：直接查看最近一次保存的回答与规则判定，展开“录入下一次回答”后可粘贴新回答再测。填写区仅显示启用用例，空回答禁止提交；历史记录保留逐项失败原因。人工规则通过不证明引用真实或史实准确。

在独立大盘中，管理员可以点击“运行核心 6 项”或“运行全部 30 项”。页面轮询实际批次进度，展示规则通过率、平均用例耗时（仅包含已采集的有效样本）、执行错误数及待复核数。空值保持“未采集”；回放耗时不是线上真实模型性能基线。

历史图表展示计划/通过数量和已完成批次的规则通过率，未通过项环形图按执行状态或规则判定分类，不推断根因。时间筛选和趋势仅覆盖当前历史页，每页最多 20 个批次；不同批次可能采用不同用例，没有完成同条件核对时不显示涨跌比较。图表采用 SVG，并提供悬停提示和键盘操作。

测试记录支持场景、模式、结果及关键词组合筛选；批次指标不会随表格筛选改变。点击“查看轨迹”打开适配窄屏的抽屉，可看到问题、实际回答、真实 Run/Thread/Batch ID、逐项期望与实际、引用原文/页码/版本，以及按持久化事件序号排列的工具参数和返回结果。JSON 支持高亮、折叠和复制。轨迹只显示可观察事件，不显示模型内部思维链或虚构裁判分数。超时/取消测试若满足预期终态可以通过，执行状态和规则判定分开显示。

管理员可以取消在途评测、重跑未通过项、追加人工复核。重跑创建关联原批次的新记录，原始失败和人工意见不会被覆盖。具有 `governance:read` 权限的用户可以读取、筛选和导出；启动、取消、重跑和复核均由后端校验管理员权限。

没有历史记录时显示空状态。运行错误、缺失观测、没有回答均不能算通过。旧版手动录入功能保留在“人工观测评测”区域；离线回归结果不再计入线上回答准确率。

## 本版测什么

自动评测执行真实认证、Gateway、RunManager、星羲 Graph、工具、检索、引用/拒答中间件和运行日志；模型回复由固定脚本提供。每批创建全新 SQLite 与合成资料 Release，每个用例创建独立会话，多轮追问只复用该用例自己的会话。业务数据库仅保存评测队列和结果，合成知识不会写入业务知识库。

| 场景 | 实际检查 |
| --- | --- |
| 有据回答 | 调用检索，引用存在，页码/文档/Chunk 对应原文且具有授权 |
| 无证据拒答 | 检索确实为空，有明确回答，不凭空引用；规则检查历史不存在断言 |
| 错误引用 | 脚本模型注入不存在的引用，最终回答必须去除它 |
| 来源撤权 | 索引仍在时撤销来源授权，真实检索不得返回其证据 |
| 超时 | 挂起模型后，评测器在期限到达时调用真实取消接口并确认终态 |
| 主动取消 | 在模型等待期间调用取消接口，确认 Run 已中断 |
| 古文释义 | 实际调用释义工具并保留“未详”等不确定性 |
| 含指令资料 | 测试指令确实出现在检索资料中，绑定和调用的工具符合产品白名单 |
| 多轮追问 | 同一独立会话创建两次真实 Run，保留两轮工具轨迹 |
| 指定来源 | 限定不存在的来源时，不得返回其他来源的资料 |

核心集为前 6 类的 pro 模式；全部集合为 **10 类 × 3 种模式 = 30 项**。这不是方案中全部 30 类领域问题的覆盖证明。真实史料质量、矛盾史料的解释、跨 Release 切换、检索召回质量和更广泛的故障注入仍需后续独立用例。

回放模型的行为已固定，因此这些结果不能证明真实模型会选择正确工具、抵御提示注入或作出正确的历史判断。报告中的规则检查也不是语义评分。真实模型批量评测、重复采样、A/B 比较、性能/费用基线属于后续范围；当前没有 `eval-agent-live` 命令，Token/费用未采集时保留空值。

## 本地命令与报告

先安装项目现有开发依赖（Python 3.12、Node 22、pnpm 和 Playwright Chromium）。在仓库根目录运行：

```bash
make eval-smoke
make eval-agent
make eval-agent TEST_ARGS='--case grounded-pro --case revoked-pro'
make test-report
make test-report TEST_ARGS='--checks backend frontend --timeout 900'
```

Agent CLI 使用与页面相同的仓储和任务执行器，但队列也放在独立本地数据库；**CLI 批次不会自动出现在业务页面**。页面启动的批次保存在当前服务数据库，刷新或重启后可以继续查看。全局 SQL 租约将并发限制为 1；过期执行被标记为错误，需要新建重跑批次，不会静默重做并覆盖结果。用例等待上限为 30 秒（超时场景 1.5 秒），批次上限为 15 分钟。

CLI 在终端打印实际报告路径：

```text
reports/testing/agent-<时间>-<随机号>/<批次 ID>/
  index.html          可离线打开的用例详情、检查表、证据和时间线
  summary.md          可供审阅的文字记录
  results.json        全部结构化结果、用例快照和人工复核
  results.csv         逐用例表格
  manifest.json       文件大小、SHA-256、执行环境和版本
  worker.log          隔离 Gateway 日志（本地保留）
```

页面批次的本地产物位于 `DEER_FLOW_HOME/evaluations/<批次 ID>/`，也可直接在页面导出 MD、CSV、JSON 和独立 HTML；导出总是读取持久化结果，因此追加的复核会进入导出。

软件测试的汇总位于 `reports/testing/software-<时间>-<随机号>/index.html`。每项保留真实命令、退出码、耗时和日志，并解析 JUnit/Rstest/Playwright 原始计数；取不到计数时显示未取得结果。报告缺失或测试启动失败仍留记录，不会视为通过。后端 JUnit 中的 collection error 也会展示为错误。

Playwright 同时生成 HTML 和 JSON，首次失败即保留 trace、截图、视频；只有浏览器实际启动并运行过场景才可能有这些附件。浏览器启动前就失败时，应查看命令日志。可以使用 `cd frontend && pnpm exec playwright show-report <报告目录>` 查看交互式 trace。默认软件检查包含模拟后端的页面测试和真实 Gateway 的已有回放测试；环境阻止端口监听时无法完成这两类浏览器验收。

成功返回 0，断言失败返回 1，执行错误返回 2。CI 会保留报告 7 天并检查 HTML/JSON 文件存在；本地报告不会自动清理，按需要归档或删除整个旧批次目录。不要单独删除正在执行的批次。

## 开源项目与实现映射

- [pytest](https://github.com/pytest-dev/pytest)：后端回归、JUnit 原始结果。
- [Rstest](https://github.com/web-infra-dev/rstest)：既有前端单元测试与 JSON reporter。
- [Playwright](https://github.com/microsoft/playwright)：页面验收、HTML、trace、截图和视频。
- [Promptfoo](https://github.com/promptfoo/promptfoo)：借鉴版本化用例、确定性断言、失败解释与数据导出的组织方式；本版未安装 Promptfoo。
- [Langfuse](https://github.com/langfuse/langfuse)：后续真实模型追踪可复用项目已有集成；本版隔离回放关闭外部 tracing，无需平台账号。

实现位于 `backend/app/gateway/evaluations/`，用例与语料在 `suites.py`/`corpus.py` 中版本化；持久化位于 harness 的 `persistence/operations/evaluations.py`。合成回放模型和语料加载器只能在隔离评测子进程模式运行。模型调用的内部思维链不进入评测投影；时间线保存可观察的工具调用和执行事件。
