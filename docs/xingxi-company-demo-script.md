# 星羲弦沚公司内部演示讲稿

适用场景：向不熟悉项目的公司同事展示产品。全程约 18—20 分钟，包含页面切换与操作；重点放在知识图谱、文史检索、古舆地图。正文可以直接口述，“演示动作”和“讲者备注”供讲者使用。

演示顺序：知识图谱 → 文献库 → 文史检索 → 古舆地图 → 星羲智能体 → 研究项目 → 古文展签 → 异名辨析 → 质量中心 → Agent 评测 → 运营中心 → 最近研究 → 账号与设置。

演示主线：以“灵岩山文史研究”为例，先看人物和地点之间有什么联系，再看这些联系来自哪些书；接着直接提问、打开出处，最后在地图上看地点、沿革和研学路线。其余模块结合这个例子逐一介绍用途。

## 演示前准备（不口述）

- 使用管理员演示账号，逐一打开上述入口，确认现场账号能看到文献库、研究项目和治理页面。侧栏顶部“星羲智能体”、下部历史会话、底部账号与设置也要带到。
- 在知识图谱准备一个可浏览的真实关系群组，优先选择灵岩山或陆玩，并确认至少一条连线的原文可以打开。工作图谱中含待复核内容，讲解时保留页面上的状态。
- 在文献库准备《（民国）宋平江城坊考》的真实记录及可访问原件；核对“陆玩和灵岩寺有什么历史联系？”的实际检索结果与引用，特别注意原文中的“或曰”。
- 准备同一问题的真实历史会话，以及一份已处理的、有内部使用许可的文献。现场生成较慢时可以切换，说明这是此前保存的结果。
- 在古舆地图试好灵岩山点位、历史时间轴、一个三维模型和研学路线。上传、影像重建等耗时操作展示入口或真实既有结果即可。
- 准备真实研究项目、可用的古文选段及出处。异名辨析只有备好真实候选名和对应资料出处编号时才提交；否则展示用途和输入方式。
- 质量中心、评测和运营页面使用真实记录；没有记录时展示入口，不补写数量或通过率。提前逐页彩排，按[本机前端运行说明](native-frontend-performance.md)核对现场版本。

## 开场（约半分钟）

**演示动作：** 打开知识图谱 `/workspace/knowledge-graph`，展开左侧栏。

各位同事，今天给大家看一下“星羲弦沚”。它主要帮助我们查找和使用吴文化、木渎一带的文史资料。

比如，要写一篇灵岩山的介绍，或者准备一条木渎研学路线，我们需要知道这里发生过什么、和哪些人物有关、这些说法记在哪本书里。今天就围绕这个例子，带大家把左边这些模块走一遍。

我们先从最直观的知识图谱看起。

## 1. 知识图谱：看清人物、地点之间的联系（约 3 分钟，重点）

**演示动作：** 管理员选择“工作图谱（含待复核关系）”，先看关系群组，再在主体目录中查找“灵岩山”或“陆玩”。选择实际有记录的主体，点击一条连线，打开关系详情和资料出处。

大家看到的这些点，代表资料里的人物、地点、建筑或文献；点之间的线，表示它们有什么联系。

我们先找灵岩山。选中以后，就能沿着已有的连线，看看哪些人物、地点和文献与它有关。再点其中一个人物，还可以继续往下找。

假如要做灵岩山的专题，一开始可能只知道这个地名。顺着图谱，我们就能发现接下来值得查的人物、建筑和相关记载，把一个宽泛的题目逐步变成具体问题。

现在点开这条线，右边会显示它表达的关系，以及支持这条关系的原文。这样我们看到一条感兴趣的线索，就能继续去找依据。

**演示动作：** 在实际可用的关系详情中指向审核状态；必要时切换“已通过”筛选，展示已核验的关系。主流程不现场修改审核结论。

这里也会标出哪些关系已经核验，哪些还在等待确认。做内容时，我们就能分清哪些可以继续采用，哪些需要先查证。

对于公司来说，图谱很适合用来找选题、梳理人物关系、准备专题内容。研究人员整理过的线索，后面的人也能接着使用。

这些点和线背后都有具体文献，我们接着到文献库看看它们的来源。

**讲者备注：** 按现场实际关系讲解，不预设“陆玩—灵岩寺”一定有直接连线。“出自文献”只表示出处联系，同见于一本书不能讲成两个人物有直接关系。工作图谱包含待复核记录；图谱中出现地点名称，也不代表已经有地图坐标。

## 2. 文献库：把资料集中起来，找到原书和出处（约 1 分半）

**演示动作：** 打开 `/workspace/library`，搜索“宋平江城坊考”，展示实际书名、版本、文件与原件入口；再打开“上传文献”查看来源登记和文件选择。

这里就是文献库，可以把我们使用的地方志、古籍和研究材料集中管理。

刚才图谱里的一条关系，可以追到某一本文献。在这里，我们能查看这本书的名称、版本和已有文件，权限允许时还可以打开原件。

以后公司有了新资料，管理员可以从这里登记来源、上传文件。系统会帮助读取文字、整理内容，从能够识别的记载里提出关系线索，再交给研究人员核对。

**演示动作：** 指向上传弹窗中的内部解析选项，以及已有文件旁的“生成图谱”；随后展示提前准备的真实处理结果，避免现场等待整本书处理。

比如补充一本关于木渎的地方志，我们可以从这里开始整理，让这份资料后续用于查找和研究。大家发现新线索时，也能回到同一份原件继续核对。

有了这些资料，接下来就可以直接提问，试着找一段我们需要的记载。

**讲者备注：** 上传与生成图谱须符合资料使用许可，处理后形成的候选仍需复核。上传成功、文字核对、关系审核分别看实际记录；不凭文件行的绿色状态判断整条处理流程成功。详细任务状态和失败原因放在运营中心查看。

## 3. 文史检索：直接提问，带着出处看回答（约 3 分半，重点）

**演示动作：** 打开首页 `/workspace`。先指向输入框，再简要切换“今日选题”“文献线索”“专题阅读”，最后回到输入框。

这是文史检索，也是日常查资料最方便的入口。大家可以像平常说话一样，把想了解的问题直接输进来。

如果一时不知道从哪里开始，也可以看看“今日选题”；想先看有哪些材料，可以切到“文献线索”；想围绕一个主题读下去，可以看“专题阅读”。这些入口帮助我们从问题或文献开始探索。

我们就问刚才图谱引出的一个问题。

**演示动作：** 输入并提交下面的问题；如果当天有同题选题，也可以直接点击进入。

> 陆玩和灵岩寺有什么历史联系？请根据本地文献回答，保留有待确认的说法，并给出出处。

系统会在当前可用资料里查找相关记载，再整理成回答。大家可以看到查找过程，也可以在得到回答后继续追问。

对我们日常工作来说，它能帮忙先找到相关材料、看懂大致内容，让编辑和研究人员更快进入正题。

**演示动作：** 指向实际回答中的资料引用，点击打开“资料出处详情”；展示书名、页码、原文，原件可访问时点击“打开原件”。

比如，这里引用了《宋平江城坊考》。我们点开以后，就能看见具体用了哪一段文字，记录了哪些出处信息，还能继续打开原件。

这一步很实用。以后写文章、做讲解词，拿到一段回答，还可以顺着它回到原文，看看这句话到底是怎么说的。

以我们提前核对的这条记载为例，原文里有“或曰”，大致就是“也有人这样说”。介绍陆玩与灵岩寺的联系时，就应该保留这个意思，说清这是文献记载的一种说法。

**演示动作：** 时间允许时追问一句；已有结果可直接展示。

> 请用普通读者容易理解的话，解释刚才引用的这段原文。

如果古文看起来有难度，还可以请它继续解释。我们就能从“找到材料”往前走一步，理解材料，再准备自己的内容。

这一页适合回答具体问题；遇到要看位置、看历史沿革，或者设计一条参观路线时，就可以接着打开古舆地图。

**讲者备注：** 以实际回答为准，现场未保留“或曰”时指出需要修订，不照稿称赞结果。未命中时说明当前可用资料里尚未找到依据。来源评级、待复核状态与公开使用权限按实际显示解释，不把能检索等同于已审核或可公开使用。

## 4. 古舆地图：把历史放到地点上看（约 4 分钟，重点）

**演示动作：** 打开 `/workspace/map`，定位木渎与灵岩山区域，选择灵岩山等实际可用点位，展示“概览”“沿革”“来源”。

现在切到古舆地图。在这张现代底图上，我们可以看木渎及周边地点的位置，再点开它们的介绍、历史沿革和资料来源。

刚才我们在文字里查灵岩山，现在就能知道它在哪里、周围还有哪些地方。对不熟悉当地的人来说，这样会更容易把书里的地名和实际位置联系起来。

**演示动作：** 在底部时间轴选择已彩排的“灵岩山建寺活动”或“永安桥始建”，查看对应地点、年代和出处；短暂播放后暂停。

下面是历史时间轴。点一个事件，地图就会转到对应地点，我们可以看看这个地方在什么时期发生了什么变化。

比如一座桥的始建、一个寺院的沿革，放在时间和地点上一起看，就更容易理解。这里也会显示事件来源；像标着“景点参考”的内容，可以作为继续查资料的线索。

**演示动作：** 选择一个带“3D”标记的地点，打开模型页签，旋转、缩放；主流程只加载一个模型。

有些地点还带了三维预览。我们可以旋转、放大，换个角度看看建筑或局部场景。做讲解准备时，这比只看一张图片更直观。模型可以辅助观察，讲历史沿革时仍要结合文献来说明。

**演示动作：** 简短打开“创建点位”和“创建模型”，指向地图选点、接入已有模型、上传影像重建等入口，然后关闭；有真实完成结果时展示结果。

后续想补充内容，管理员也有操作入口：在地图上增加地点，为地点接入已有模型；配置好影像重建服务后，还可以上传拍摄素材，生成可浏览的三维内容。

**演示动作：** 切换“研学路线”。目录暂无路线时，默认显示“木渎古镇人文半日研学（示例）”，依次为永安桥、明月古寺、虹饮山房、古松园。上移一个站点，移除后再从“选择添加站点”加回，点击“导出研学提纲”；需要重来时点击“恢复示例”。

如果是做研学活动，我们还可以把地点组织成路线。这里先看一条木渎半日研学示例，我们能添加或移除站点、调整先后顺序，再把研学提纲导出来。

比如从一座桥讲到寺院，再走到园林，每一站安排讲什么、看什么，都可以围绕这些地点继续准备。路线修改保留在当前页面，导出的提纲方便我们后续完善活动方案。

所以，这一页既能帮助大家认识地方，也能辅助准备讲解、安排参观和设计研学活动。实际出行时，再结合开放时间和现场条件调整。

**讲者备注：** 时间轴只演示实际存在的事件，年代范围不能讲成确定年份。景点参考、待复核草稿和已审核记录保留各自标识；近似坐标保留定位说明。三维预览不宣称为经过考证的历史复原；现场不等待上传或重建完成。新建点位、模型与文献审核、知识发布分别管理。

## 5. 星羲智能体：从研究场景开始对话（约半分钟）

**演示动作：** 点击侧栏顶部“星羲智能体” `/workspace/agent`，展示研究场景和“开始对话”，不再重复生成一次问答。

左上方的“星羲智能体”，提供了另一个开始研究的入口。这里可以先看看选题发现、史料复核、专题综述等使用场景，再开始对话。

比如我们想围绕木渎水系做个专题，可以参考这里的示例组织问题。它帮助我们把“想了解一个地方”，变成一个更具体、可以继续查的问题。

**讲者备注：** 场景卡片是研究示例，不作为已经完成的研究成果展示。

## 6. 研究项目：把同一个专题的材料放在一起（约 45 秒）

**演示动作：** 打开 `/workspace/projects`，进入真实的“灵岩山文史研究”项目，展示关联文献、研究问题、笔记和阶段结论。

如果这项研究要持续做，就可以建立研究项目。

比如灵岩山这个专题，我们能把使用的文献、要解决的问题、阅读笔记和阶段结论放在一起。下次回来，可以沿着原来的记录继续，也可以只围绕项目里的文献提问。

它适合一篇专题文章、一场展览或一套研学课程的长期准备，让材料和研究过程更容易找回来。

## 7. 古文展签：把一段古文做成易读的说明（约 45 秒）

**演示动作：** 打开 `/workspace/glossary`，填入提前核对的原文和出处，展示原文与释读并列的结果，以及“复制展签”“打印”。

查到古文以后，如果要让普通读者也能看懂，可以用古文展签。

把一段原文、书名和已知页码填进来，就能生成原文和释读并列的阅读说明。核对好以后，可以复制或打印，继续用于展陈文字、活动手册和讲解准备。

这样，一段原本需要解释的古文，就有了更方便阅读和使用的形式。

**讲者备注：** 默认《桃花源记》选段只用于演示交互，不称为吴文化资料成果。正式使用前核对释读，未知页码留空。

## 8. 异名辨析：遇到不同叫法，先把对象弄清楚（约半分钟）

**演示动作：** 打开 `/workspace/name-authority`，指向研究语境、候选名称和资料出处输入；只在备有真实证据时提交。

查地方文史时，经常遇到一个地方有几个名字，也可能是不同地方用了同一个名字。

异名辨析就是帮助我们核对这些叫法。把名称、具体研究范围和支持它们的资料放在一起，看看能否确定当前使用的名称；暂时判断不了的，就留给研究人员继续确认。

做文章、图谱和地图时，这能帮助我们减少叫错名字、把两个地方混在一起的问题。

## 9. 质量中心：发现问题后，有地方跟进（约半分钟）

**演示动作：** 打开 `/workspace/quality`，展示一条真实反馈及处理状态；没有反馈时展示空页面与入口。

如果发现回答有误、引用对不上，或者资料有遗漏，可以把问题反馈回来。负责人员在质量中心查看、复核，记录处理意见。

比如刚才某一句话把传说讲成了定论，就可以把这个具体问题记下来，后面跟进修正。

## 10. Agent 评测：改动以后，检查原有功能还能不能用（约半分钟）

**演示动作：** 打开 `/workspace/evaluations`，展示真实测试批次；有记录时打开“查看轨迹”，没有时介绍页面用途。

这一页主要给维护人员使用。系统更新以后，可以用一组测试检查检索、回答和引用等流程是否仍然正常，并查看哪里出了问题。

这里目前主要是固定场景的自动检查。它帮助我们发现软件问题，文史内容对不对，还要回到真实资料和人工核验。

## 11. 运营中心：查看处理进度，跟进失败任务（约半分钟）

**演示动作：** 打开 `/workspace/operations`，先看“任务恢复”，再指向“修订记录”和“资产版本”；其余指标按真实采集情况展示。

运营中心主要帮助负责维护的同事了解：资料处理到哪一步，有没有失败，哪些任务可以重试，最近又做过哪些修订。

比如上传一本书后还没有可用结果，就可以到这里检查具体卡在哪一步，继续处理。资料和内容的版本也能在这里追踪，方便后续维护。

## 12. 最近研究：找回上次的问题，接着查（约半分钟）

**演示动作：** 打开 `/workspace/chats`，进入此前保存的真实研究会话；再指向侧栏下部的历史会话快捷入口和更多操作。

最近研究保存了我们之前的对话。上次查到哪里、用了哪些引用，下次都可以回来看，并沿着原来的问题继续追问。

侧栏下面也能快速打开最近的会话，还可以重命名、导出研究记录。这样，查资料的过程可以保留下来，后续整理文章或报告时也方便回顾。

## 13. 账号与设置：按自己的习惯使用（约 15 秒）

**演示动作：** 点击侧栏底部账号区域，打开设置，简要指向外观和账号设置后关闭。

最下面是账号和设置，可以查看账号信息，调整界面外观等使用偏好。日常按自己的习惯设置好，就可以继续查资料了。

## 结束语（约 15 秒）

**演示动作：** 回到刚才带有原文引用的回答，或停留在灵岩山地图。

以后要准备一篇地方文化文章、一次展览讲解或一条研学路线，就可以从这里开始：用图谱找线索，用检索查资料，再到地图上看地点，把找到的内容逐步整理成能用的成果。今天的演示就到这里。

## 现场衔接用语（不口述整节，按需使用）

需要重启时，先执行：

```bash

bash /data/laikai/heikesong/deerflow-native/start.sh start
```


将 服务器IP 替换成你平时 SSH 连接的地址；用户名和 22 也按实际 SSH 配置修改。

3. 在外面电脑的浏览器打开：

http://localhost:12026

网页和 API 都走这个入口，只需转发 12026。保持 SSH 窗口开启，按 Ctrl+C 结束转发。
