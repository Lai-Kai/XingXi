# 文献库状态与资料编辑修复验收

2026-10-17：真实前端日志中的编辑错误是对空 `edition` 调用 `.trim()`；导入资料允许版本未知，编辑时应显示空输入并保存为 `null`。登记新来源仍要求填写版本。

真实入库失败发生在《（光緒）常昭合志稿》的内部工作版本准备阶段：108,934 个 Chunk 的全文索引查询一次展开全部 ID，触发 SQLite `too many SQL variables`。后台随后重新发布同一 manifest，又触发唯一约束。索引现在分批查询 Chunk 和已有 Evidence；同一失败/准备中的内部版本继续重试原记录。

文献库现在独立显示：

- **文本复核**：最新切分版本中的所有片段及其精确引用的清洗页。缺页或待复核项保持待复核，旧版本的通过结论不代替新版本结论。
- **入库处理**：最新任务的真实状态。复核决定和完成复核后重新向服务端读取；完成复核只推进后续处理，页面不提前标成已完成。

图谱关系复核单独记录，不能据此推断整本文献文本已经复核。只读核查中，报错文件的文本状态仍是 `pending`、任务为 `failed`；新聚合查询已在真实库成功返回，未修改业务数据或活动版本。

## 在宿主终端启用

本机原生 Gateway 没有启用源码热重载。当前编码环境与宿主网络及进程隔离，无法代为重启。当前问答/处理结束后，在服务器普通终端执行：

```bash
bash /data/laikai/heikesong/deerflow-native/start.sh stop
bash /data/laikai/heikesong/deerflow-native/start.sh start
```

如果遇到先前的 8001 端口预检问题，使用[已有启动器排查说明](xingxi-answer-policy-activation.md#停止后仍报-8001-占用)。无需重新导入或重做已保存的复核。

## 页面检查

1. 刷新文献库，在上述文件行分别核对“文本复核”和“入库处理”。
2. 点击“编辑资料信息”，确认版本未知时仍能打开、修改名称、保存并重新读取。
3. 点击失败行的“重试处理”，等待处理进度更新。处理成功后仍保留真实的待复核/已复核结论。
4. 对页和片段提交复核，列表应更新；点击“完成复核”后按后台任务的后续处理状态显示。
