# 建筑模型加载修复

问题入口为点位的“3D 建筑研习”，与原生高斯 PLY 的显示方式无关。正式入口已复现古松园加载超过 120 秒后显示失败；模型文件未返回解码错误。七个原 GLB 文件头、大小和 HTTP HEAD 均正常，服务器内部完整读取古松园 71,633,044 字节分别为直接前端 0.158 秒、统一入口 0.146 秒；本地转发读取前 1 MiB 为 23.265 秒。该测量确认本次转发读取较慢，不等于所有用户网络均为此速率。原模型还带有约百万顶点和 4096×4096 贴图。

## 修改

- 七个静态模型使用独立、带摘要的流畅预览副本。古松园约 3.7 MiB；默认减少网络与渲染开销，原件路径、大小、摘要、点位绑定与说明保持。
- “建筑模型精度”可切到“原始精度”，也可下载原件。轻量副本只用于浏览，几何细节与贴图精度会降低，不替代原件。
- 连续 120 秒没有严格增加的有效进度才报加载停滞；有进展的大文件不受原来的两分钟总时限限制。15 秒无进展给慢加载提示；设备渲染中断和文件失败分开提示。
- 不重新训练，不修改权限或数据库，不改动高斯/离散点与 RGB 文件。

## 可复用生成

`scripts/prepare-map-previews.mjs` 读取原模型，另存副本并验证原件摘要。使用隔离工具目录安装清单中固定版本的 `@gltf-transform/core`、`@gltf-transform/extensions`、`@gltf-transform/functions`、`meshoptimizer` 和 `sharp`，设置 `XINGXI_GLTF_TOOLS` 为该目录，再传入原模型目录和新的输出目录。只使用 CPU；不要原地替换原文件。具体参数和每个文件的大小、面数、贴图、摘要见 `map-glb-previews-20261029.json`。简化方法参考官方 [simplify](https://gltf-transform.dev/modules/functions/functions/simplify) 与 [textureCompress](https://gltf-transform.dev/modules/functions/functions/textureCompress) 文档；这不是重建质量验收。

## 验证

类型检查、定向 ESLint 和 8 项单元回归通过，覆盖持续进展超过两分钟、停滞/重复进度、慢加载提示、取消清理、精确绑定和七个预览 GLB 摘要/体积。候选生产构建通过（181.56 秒），4 项浏览器回归通过（45.61 秒），覆盖七模型真实渲染、视角/缩放/放大、失败重试、原件显式切换与手机布局；正式入口真实鉴权、零业务接口模拟复核古松园约 4.76 秒、木渎古镇约 2.88 秒完成预览验证，旋转可用、原始 GLB 自动请求 0 次、页面错误 0；七个原件与预览副本摘要及预览 HTTP 200 再核对通过。

浏览器四项回归中的地图业务数据使用夹具，七个 GLB 文件为实际生成的轻量副本；原始精度切换/失败恢复检查使用显式受控失败，不等于原始大文件在慢连接中的完整浏览器渲染已验收。正式入口两点复核未模拟业务接口。单次本机测量区间包含模型就绪后的拖动及截图，不代表所有网络的固定耗时。此次不更改原生高斯与 RGB 文件，未启动 GPU 训练，未修改权限、数据库、Gateway 或 Nginx 进程。
