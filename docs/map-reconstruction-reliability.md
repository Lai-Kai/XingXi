# 地图重建可靠性修复（2026-10-24）

本次落实项目检查中的四项高优先级修改。

- Gateway 启动时恢复持久任务状态同步，默认每15秒读取活动任务，最多同时核对4个远端状态。后台同步只检查已有任务，不调度GPU，也不自动重启训练。地图可见期间每15秒刷新已接入模型，关闭创建面板后仍能显示完成结果。
- GET 任务详情仅检查状态。传送失败的显式“重试连接”调用管理员 POST `/{id}/retry-connection`，复用任务ID；终态不会重新提交。
- 远端监督器在 `.started/supervisor.json` 保存机器启动标识、监督/子进程PID及启动指纹和心跳。失活任务转为 `failed`，保留防重标记及中间文件。旧任务采用保守兼容检查；无远端目录的传送记录等待120秒后记为未启动。发现残余进程时提示管理员核对，禁止自动重复训练。
- Native Gateway 使用 `DEER_FLOW_HOME/gateway-upload-tmp` 专属0700临时目录。鉴权和CSRF后、multipart解析前检查临时与持久副本的空间，并为并发请求记账，保留512MiB余量。未知长度的请求按现有上限预算，实际字节数继续受限。ENOSPC/EDQUOT及其解析包装错误返回507；原有大小限制仍返回413。
- `scripts/capture_native_release.py` 在不改动Git工作树的情况下，保存带哈希的公开源码快照、已删除/排除文件清单、原生部署脚本、构建标识和迁移版本，并提供verify与恢复说明。真实配置、密钥及数据库内容另行私密备份。快照不冒充干净提交，不自动提交既有协作者改动。

验证与部署收据保存在本次修复报告中。初始全套后端测试在隔离源码副本因缺少真实Git仓库标记而收集失败；定向回归覆盖本次变更及既有地图/重建/FLUX/权限路径。未启动真实GPU训练；不以CPU假远端测试声称训练质量或全仓全部通过。

回滚必须使用部署记录中的修改前文件和旧前端构建目录；只切换已验证的Gateway/前端进程，保留Nginx及训练任务。不要清理旧训练结果或重置他人的Git改动。
